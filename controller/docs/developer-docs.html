1. 双协议接入对比

本站同时支持 OpenAI 兼容接入和 TD 公共协议接入，可根据现有客户端任选其一，无需同时接入。两种方式使用相同的平台 API Key，沿用账号的模型权限、分组与额度；选择协议不会扩大模型权限，也不代表每个模型都支持相同的参数、素材或操作——具体以各模型参数页为准。

3. 方式一 · OpenAI 兼容接入

已在用支持 OpenAI 媒体接口的 SDK 或应用时选这种方式。不携带 X-TD-Contract。

export BASE_URL='http://39.107.108.35:3000'
export OPENAI_BASE_URL="$BASE_URL/v1"
export API_KEY='替换为你的平台令牌'

# 查看模型目录
curl --fail-with-body "$OPENAI_BASE_URL/models" -H "Authorization: Bearer $API_KEY"

视频创建、查询与下载

curl --fail-with-body "$OPENAI_BASE_URL/videos" \
  -H "Authorization: Bearer $API_KEY" \
  -H "Idempotency-Key: 生成一个UUID，重试时复用" \
  -H "Content-Type: application/json" \
  --data-raw '{
    "model": "wan3.0-video",
    "prompt": "海边日落，镜头缓慢向前推进",
    "seconds": "2",
    "size": "1280x720"
  }'

保存响应中的原始 id，每隔数秒查询一次并遵守 Retry-After。 只在 status=completed 后下载；failed 时停止并读取 error。 客户端超时后保留任务 ID，不要自动重新创建。

curl --fail-with-body "$OPENAI_BASE_URL/videos/$VIDEO_ID" -H "Authorization: Bearer $API_KEY"

# 只在 status=completed 后执行
curl --fail-with-body --location "$OPENAI_BASE_URL/videos/$VIDEO_ID/content" \
  -H "Authorization: Bearer $API_KEY" --output video.mp4
  • 下载可能返回媒体或 302；跨站重定向不得转发网关 Key／Cookie（curl 默认即凭据隔离，不要用 --location-trusted）
  • 签名直链模式 HEAD 返回 405／Allow: GET，应使用 GET；这不表示生成失败
  • 视频取件不能依赖任务 JSON 一定有顶层 video_url
各模型的 OpenAI 风格字段支持度不同：请以具体模型参数页为准，不要把某个模型的示例照搬到另一个模型。

4. 方式二 · TD 公共协议接入

调用前确认三件事

  1. 模型 ID：请求中的 model 必须与模型页一致，保留大小写和空格
  2. 生成模式与素材：确认是否支持你需要的模式，以及素材格式与数量限制
  3. 必填参数与结果方式：使用该模型自己的参数和示例，确认是直接返回结果还是返回任务 ID
export BASE_URL='http://39.107.108.35:3000'
export API_KEY='替换为你的平台令牌'

# 查询当前令牌实际可用的模型目录
curl --fail-with-body "$BASE_URL/v1/catalog/models" -H "Authorization: Bearer $API_KEY"

目录中 data[].x_td 附带能力元数据：contract_id（公共协议）、parameters（字段类型、必填项、默认值和取值范围）、inputs / reference_media / media_constraints（素材传输方式与限制）、async 与 result（结果约定）。模型页面展示公开能力，Key 目录展示个人实际可用能力；有差异时以 Key 目录为准。

TD 视频接口 · 公共字段

POST /v1/videos，携带 X-TD-Contract: td.video.v1。视频按异步任务处理，创建后保存响应中的 id。

字段含义使用规则
model对外模型 ID必填，选择 td.video.v1 模型
prompt内容、动作与镜头描述必填条件以模型为准
mode生成模式只使用模型公布的模式
duration输出时长（秒）类型与范围以模型为准；部分模型保留 -1（自动时长）
resolution分辨率档位按模型目录填写，不可跨模型照搬
ratio画面比例固定比例或自适应的支持范围由模型决定
input.media素材数组每项使用 type 与 url
parameters模型扩展参数只放当前模型声明的扩展字段

素材角色：

模式典型素材配置
text_to_video仅提示词，无素材
image_to_videofirst_frame，具体附加素材按模型要求
first_last_framefirst_frame 与 last_frame
multi_ref模型允许的 reference_image、reference_video、reference_audio 等角色
{
  "input": {
    "media": [
      { "type": "first_frame", "url": "https://example.com/start.png" },
      { "type": "last_frame", "url": "https://example.com/end.png" }
    ]
  }
}
  • 素材数量、大小、时长、允许角色及混用条件必须满足所选模型限制；素材 URL 的有效期应覆盖生成时间
  • 扩展字段放在 parameters 中，使用当前目录给出的字段名；目录没有声明的字段不要自动补入，不使用的可选字段直接省略，不传 null；显式 0、false 与省略字段含义不同
  • 自动时长可能影响预扣额度，价格及结算规则以控制台和模型说明为准

TD 图片与音频

  • 图片：POST /v1/images/generations（文生图）与 POST /v1/images/edits（参考图编辑），携带 X-TD-Contract: td.image.v1；同步响应读取 data[].url 或 data[].b64_json
  • 音频：POST /v1/audio/speech，携带 X-TD-Contract: td.audio.v1，使用模型支持的 input/voice/response_format/speed，成功响应为音频字节

5. 模型参数 · wan3.0-video-prime

TD 协议 POST /v1/videos 的请求参数（OpenAI 风格字段请见第 3 节，两种风格不要混用）。

mode素材要求

image_to_video一张首帧图片
first_last_frame首帧、尾帧各一张图片
multi_ref至少一份参考素材，不传首尾帧

type数量上限说明

last_frame1尾帧图片

reference_video5参考视频（单段 1–15 秒，合计 ≤15 秒，需平台可确定时长）

  • 首尾帧不能与参考素材混用，尾帧不能单独使用；按请求中参考图片的顺序编写 @参考图N，无需自行重排

7. 模型参数 · wan3-single（共享车）

wan3-single 与 fleet-shared 是同一共享服务的两个名称，使用相同的分组权限、报价、扣费与队列；已有 fleet-shared 权限的令牌可直接使用 wan3-single。

查询报价：GET /v1/fleet/catalog，共享车每条价格取 fleet-shared.task_prices 中对应的 480P、720P、1080P 价格。即使使用 wan3-single 提交，也从目录的 fleet-shared 条目取价。

字段类型规则
modelstring必填，wan3-single 或 fleet-shared
promptstring提示词与素材至少提供一项；最多 20,000 字符 / 65,535 字节
durationinteger可选，默认 5，范围 2–30 秒
resolutionstring可选，默认 480P；允许 480P、720P、1080P
ratiostring可选，默认 adaptive；允许 adaptive、16:9、9:16、1:1、4:3、3:4、21:9
modestring生成模式，省略时按素材角色处理，见下表
input.mediaarray<object>可选，最多 10 项；仅支持 reference_image / first_frame / last_frame 三种图片类型（first_frame、last_frame 各 ≤1）
parameters.idstringTD 请求必填，每条任务一个 UUID；任务 ID 为 fleet_ 加该 UUID
parameters.expected_pricestringTD 请求必填，从 GET /v1/fleet/catalog 读取对应分辨率的人民币价格字符串原样填入
parameters.audioboolean可选，是否生成声音
parameters.prompt_extendboolean可选，提示词扩展开关

mode 与素材要求：

mode素材要求
text_to_video填写提示词，不传素材
image_to_video一张首帧图片
first_last_frame首帧、尾帧各一张图片
multi_ref至少一份参考图片，不传首尾帧
  • TD 请求示例：{"model":"wan3-single","prompt":"…","mode":"text_to_video","duration":5,"resolution":"480p","ratio":"16:9","parameters":{"id":"UUID","expected_price":"目录中的480P价格"}}
  • OpenAI 请求示例：{"model":"wan3-single","prompt":"…","seconds":"5","size":"1280x720"}（报价由服务端按当前报价计算）

8. 素材上传 /v1/fleet/media

curl --fail-with-body "$BASE_URL/v1/fleet/media" \
  -H "Authorization: Bearer $API_KEY" \
  -F 'type=shared' \
  -F 'kind=image' \
  -F 'token=图片1' \
  -F 'file=@./reference.png'
字段必填说明
type是固定 shared
kind是image / video / audio / file
token建议素材短名 ≤20 字符，提示词引用与 parameters.media 都要用它
file是见下表
kind格式大小上限
imagePNG、JPEG、WebP、BMP20 MB
videoMP4、MOV100 MB
audioMP3、WAV15 MB
file文件20 MB

上传返回 { "id": "…", "kind": "image", "object": "fleet_media", "seconds": null, "token": "图片1" }； 音视频保留返回的 seconds。同 token 重复上传会生成新 id。 请求超时或结果未确定时不要重复上传，保留请求信息交由平台核对。

9. 引用上传素材 parameters.media

仅共享车模型（wan3-single / fleet-shared） wan3.0-video-prime / wan3.0-video 的素材一律通过 input.media 传 URL 引用（见第 5、6 节）。 把上传返回值放入提交请求的 parameters.media，并增加素材用途 role：

{
  "parameters": {
    "media": [
      { "id": "替换为上传返回的素材ID", "kind": "image", "token": "图片1", "role": "ref" }
    ]
  }
}
字段说明
id上传返回的素材 ID
kindimage / video / audio / file
token素材短名，提示词用 @token 引用
roleref 参考 / first 首帧 / last 尾帧

素材配额：每条任务最多 20 份——图片 ≤10、视频 ≤5、音频 ≤5、文件与网页合计 ≤1； 音视频单段 1–15 秒、各自总时长 ≤15 秒；参考视频与成片合计 ≤30 秒。 共享车素材只能由上传它的令牌使用；跨渠道引用会被网关拦截（material_channel_mismatch）。

10. 人物资产 /v1/materials

接入流程：上传人物图片 → 查询资产审核 → 引用资产生成视频 → 查询视频结果。 人物资产生成能力需在平台侧为对应模型开通（catalog 中带人物资产标记的模型）后方可使用。

# 上传（multipart，仅图片，≤30 MiB）
curl --fail-with-body "$BASE_URL/v1/materials" \
  -H "Authorization: Bearer $API_KEY" \
  -F "model=$MODEL" -F 'material_type=virtual' -F 'file=@./person.png'

# 已有图片链接时用 JSON 形态
curl --fail-with-body "$BASE_URL/v1/materials" \
  -H "Authorization: Bearer $API_KEY" -H "Content-Type: application/json" \
  -d '{"model":"$MODEL","source_url":"https://…/person.png","material_type":"virtual"}'
字段必填说明
model是已开通人物资产能力的平台模型名
file / source_url是二选一：multipart 文件，或可直接读取的 HTTP(S) 图片 URL
material_type否virtual（默认）/ real

上传成功返回 {"id":"material.asset.…","object":"material","model":"…","status":"processing"}，保存完整 id 作为资产标识。 请求超时或结果未确定时不自动重新上传，有资产 ID 时继续查询原资产。

curl --fail-with-body --get "$BASE_URL/v1/materials/$MATERIAL_ID" \
  -H "Authorization: Bearer $API_KEY" --data-urlencode "model=$MODEL"
status处理
processing继续查询，不重复上传
ready可以提交目标模型的视频生成
failed停止等待，读取 error_code
unknown保留资产 ID，继续核查，不当作成功或重新入库

审核通过后引用资产生成：

{
  "model": "wan3.0-video-prime",
  "prompt": "让@参考图1中的人物转身向镜头微笑，保持人物外貌一致",
  "mode": "image_to_video",
  "duration": 4,
  "resolution": "480P",
  "ratio": "16:9",
  "input": { "media": [ { "type": "reference_image", "asset_id": "material.asset.…" } ] }
}
  • 单张人物图用 mode: "image_to_video"；人物与普通场景图混用用 multi_ref
  • 每项媒体只填 url 或 asset_id 之一；按参考图片顺序编写 @参考图N
  • 多个人物资产应由同一调用身份、兼容模型创建；平台会校验资产组合

11. 查询任务（单条 / 批量）

单任务查询

curl --fail-with-body "$BASE_URL/v1/videos/$VIDEO_ID" \
  -H "Authorization: Bearer $API_KEY"

返回任务对象（status / progress / poll_after_seconds / polling_url）。 提交与查询返回的任务对象结构相同，请按完整 id 跟踪任务。

状态码含义
200视频字节，保存为文件

  • 只在 status=completed（或统一任务接口的 succeeded）后下载；failed 时读取 error 并停止，错误 JSON 不要保存为成品
  • 支持 HEAD 与 Range 断点续传；下载可能返回媒体或 302，跟随即可，跨站重定向不会转发你的令牌

14. 计费规则

视频模型按秒计费，档位由请求参数决定（优先读 resolution，其次按 size 映射）：

档位单价（配额/秒）对应参数
480P0.45resolution:480P
720P0.9resolution:720P 或 size 1280x720 / 720x1280
1080P1.8resolution:1080P 或 size 1792x1024 / 1024x1792

扣费 = 时长 × 档位单价 × 额度单价(500000) × 分组倍率。 建议始终显式传 resolution 或 size：不传时按 720P 预扣，若实际生成档位更高会与预扣不一致。 共享车按任务预扣：钱包和 Key 额度均需充足；取消或失败的费用以任务 refunded 和账单为准。

16. 注意事项

  • Idempotency-Key：每次新建任务用新的 UUID；同一 key 重复请求不会重复建单，超时重试时复用它
  • 共享车重试：网络异常先查询原任务；重试必须用相同的 UUID 与参数，不要换 ID 重投
  • SDK Base URL：填完整 http://39.107.108.35:3000/v1；自动追加 /v1 的渠道配置只填域名
  • 素材过期：签名直链约 15 分钟有效，下载一律走本站 /content 接口
  • 素材绑定：共享车素材只能在同一渠道使用；本站已做渠道绑定校验，跨渠道引用直接报 material_channel_mismatch
  • 协议切换：复用原请求键切换协议可能返回幂等冲突，先查询原任务
